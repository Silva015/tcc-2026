\label{chap:solution}

This chapter presents TransferKAN, the model this work set out to evaluate, the hypotheses that motivated it, and the experimental design used to test them. The design isolates the contribution of each component: the head, the backbone, the split and the number of tasks.

\section{The TransferKAN Architecture}
\label{sec:transferkan_arch}

TransferKAN\footnote{The short paper derived from this work for SIBGRAPI 2026 calls the same model TransKAN.} combines a convolutional feature extractor pre-trained on ImageNet with a Kolmogorov-Arnold Network (KAN) as the classification head. It has three stages (Figure~\ref{fig:transferkan_arch}):
\begin{enumerate}
    \item \textbf{Feature extractor:} a ResNet-152~\cite{he2016resnet} with ImageNet weights~\cite{deng2009imagenet} and without its last fully connected layer. For a $224 \times 224$ image it outputs a vector of 2,048 features.
    \item \textbf{Regularisation:} Dropout with $p=0.5$ on that vector.
    \item \textbf{KAN head:} a two-layer KAN, $[2048, 128, K]$, with $K=2$ outputs for entry/exit and $K=3$ for the shooting distance. Each edge carries a learnable function made of a SiLU base term and a cubic B-spline on a grid of size 10 (Section~\ref{sec:kan_background}), implemented with \texttt{efficient-kan}~\cite{efficientkan}. The head has 3,936,000 parameters for entry/exit and 3,937,920 for distance.
\end{enumerate}

\section{Hypotheses Under Test}
\label{sec:justification}

TransferKAN was motivated by two claims about KANs used as classification heads. In the earlier version of this work they were stated as advantages; here they are treated as hypotheses, each with the result that would support it:
\begin{itemize}
    \item \textbf{H1, better discrimination:} because its edge functions are learned, a KAN head would draw finer decision boundaries than an MLP head on the same features, especially for minority classes. This would be supported by a higher AUC than the best MLP head on the same backbone, under the pre-registered rule of Section~\ref{sec:stats} (outcome A).
    \item \textbf{H2, parameter efficiency:} a KAN head would reach the same performance with fewer parameters. This would be supported by a KAN head beating an MLP head with the same number of parameters. Note that the TransferKAN head is not small: with 15 parameters per edge it has 3.94 million parameters, 15 times as many as an MLP with the same widths (262,530).
\end{itemize}

\section{Experimental Design}
\label{sec:design}

\textbf{Head ablation.} To test H1 and H2, the ResNet-152, the folds and the recipe are kept fixed and only the head changes (Table~\ref{tab:cabecas}). The linear head (a) is the simplest reference. The MLP-128 (b) has the same widths as the KAN. The matched MLP (c) has practically the same number of parameters as the KAN, so that a difference between (c) and (d) cannot be attributed to size. The KAN-8 (e) gives a KAN the parameter budget of (b). To check whether the conclusion depends on the spline basis, wavelet-KAN heads~\cite{bozorgasl2024wavkan} W1--W5 replace the B-splines by wavelets: W1 keeps the topology of (d), W2 the budget of (b) and W5 the budget of (d), and W3 and W4 change the wavelet.

\textbf{Backbones.} Twelve architectures of the study of Lira et al.~\cite{Lira2025deep}, among them the ResNet-152 and two transformers, are retrained with the same recipe and a linear head. This answers how much of the difference between TransferKAN and the published baselines comes from the backbone and its pre-training.

\textbf{Split.} The hold-out of the public code of Lira et al.\ is reproduced and compared with the case-grouped folds with everything else fixed, to measure how much the split alone changes the numbers.

\textbf{One network for both tasks.} Finally, a single ResNet-152 with two heads, one per task, is compared with the pair of single-task networks (Figure~\ref{fig:multitarefa_arch}). This variant changes the number of networks and keeps the type of head, so it measures the cost and the performance of sharing the backbone.
